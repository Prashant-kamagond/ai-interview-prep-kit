# Requirements traceability

Source: `software-engineer-assignment.pdf` (section numbers refer to it). Brought up to date in Phase 9 and Phase 10 (deployment rows)
against the code and the test runs recorded in [`verification.md`](verification.md).

**Status words.** _complete_: implemented and demonstrated by a passing test or run, within the limits stated.
_partial_: part of it is implemented or demonstrated. _missing_: not done. _unverified_: implemented, but
nothing here can show that it works in the environment that matters.

**Evidence tags.** **A** automated test in the repository. **M** automated, but against a fake (a fake
model, local fixture websites, a fake API in jsdom). **R** code review only, no test protects it. **E** a real
environment (a real browser, a real provider, a real deployment). **No row has E evidence.** Everything that
says "complete" is therefore complete _as far as fakes and a real MongoDB can show_.

Suite sizes at the time of writing: unit `pnpm test` 1,843 tests (the per-package split was not re-counted after the Groq provider was added; web 532 before it) and integration `pnpm test:integration` 213 tests against a real MongoDB (auth,
kits, jobs, generation, platform, builder, regeneration, practice, security).
